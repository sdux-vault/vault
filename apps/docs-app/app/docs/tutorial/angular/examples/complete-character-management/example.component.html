This "fully-armed and operation" Star Wars tutorial example of the complete SDuX pipeline is very complex. It is intended to demonstrate the full range of SDuX Vault capabilities. There are 5 pipeline stages that will cause you to believe the tutorial is not working correctly. You will need to carefully review the following learning points to understand how the pipeline is configured and working correctly.

  • The hydrate FeatureCell api method is enabled and will load the initial state asynchronously from a promise when the "Resolve" button it clicked. The "Reject" button will simulate a failed initial state load. The "loading spinner" will be displayed until the promise is resolved or rejected.
  • The withSessionStoragePersistBehavior is enabled and will retain the state across page loads. Check the Encrypted State textarea to see the encrypted state that is persisted in sessionStorage. The Reset State button will clear the persisted state and a browser reload will trigger the hydrate promise again.
  • The withDelayController is enabled and will introduce artificial delays in state changes especially when clicking action buttons multiple times to trigger state changes. Each state change will be delayed by 3 seconds before the state candidate is allowed into the pipeline.
  • The withDistinctUntilChangedBehavior is configured and will block state changes if they are not distinct even when clicking action buttons multiple times. That is the responsibility of the behavior.
  • The withStepwiseResolveBehavior  withStepwiseFilterBehavior and withStepwiseReducerBehavior are all configured and will block state changes until the alert "Ok" button is clicked. With the withDistinctUntilChangedBehavior enabled only the withStepwiseResolveBehavior will prompt if the values are not distinct. The other two stepwise prompts will not be displayed because the state change candidate was blocked by the distinct until changed behavior and aborted. The withDistinctUntilChangedBehavior stage is executed in the pipeline only after a state candidate has been resolved. Evaluating if the state candidate is distinct before the resolve stage would be comparing values, promises, observables, deferred values, etc. that are not yet resolved and would not be a valid comparison.

Actions
Delay Timer
The delay timer demonstrates the elapsed time the state request has been pending in the controller. The timer starts when the state request is submitted and stops when the request is resolved or rejected. The timer is reset to zero when a new state request is submitted.
The service registers a deferred hydration factory before initialize() makes it the authoritative initial State source. Resolve sends five characters through the full Replace pipeline, including the configured Filter, Taps, and Reducers. Reject emits an initialization Error and leaves the FeatureCell without a value; configured initial State is not used as a fallback. Hydration runs once during initialization and does not run again when State is reset.

Adds character data emitted by an Observable to the current collection, or sends an error through the FeatureCell error pipeline.
Creates an Angular HttpResourceRef for the public SWAPI people endpoint and passes it directly to replaceState(). Vault preserves the current collection while the request is loading, waits for Angular to resolve and validate the response, then sends the selected characters through the configured Filter, Taps, and Reducers. The finalized collection replaces the previous FeatureCell value atomically; transport, parsing, and HTTP failures enter the same error lifecycle without committing a partial response.
Replaces the current collection with its captured initial values and selects the first restored character.
Calls replaceState({ value: null }) to demonstrate null normalization. The FeatureCell intentionally persists the value as undefined, clearing the current state.
Arms an inline filter and calls replaceState() with a new Darth Maul candidate. The filter throws before State commitment. After the failure, Reset Error disarms the filter and clears the global error without starting another pipeline request.
Calls the FeatureCell's dedicated reset() API to explicitly clear the current state value to undefined without submitting replacement state.
Permanently tears down the FeatureCell, releases its runtime resources, destroys attached behaviors and controllers, completes internal streams, and prevents further pipeline execution, state updates, or emissions.
Distinct Until Changed Operator
Reconstructs Rey as a new object on every click and merges that one-character delta into the collection. The custom comparison checks every incoming identity against the previous collection, so another Rey returns VAULT_NOOP regardless of reducer sorting.
Cycles through four Jedi with a modulo index and merges the next one-character delta into the collection. The first four unique IDs proceed through the pipeline; after the modulo wraps, the repeated identity is suppressed without depending on collection order.

Tab Sync Controller and Behavior
Opens this example in another tab to demonstrate initial state negotiation and ongoing synchronization through withTabSyncController and withTabSyncBehavior. Successful Pipeline executions synchronize committed FeatureCell State values and shared resets; failed Pipeline executions leave the peer tab unchanged. Loading status, Error, Controller outcomes, form values, and other page interactions remain local to the tab where they occur. A new tab receives the last committed State with loading status set to false and Error set to null, without inheriting transient metadata from its peer.
