Tutorial

This is a guided Angular tutorial for building one complete feature with from the ground up. You will move step by step from project setup, to Feature State definition, to registration and initialization, and finally to a working UI that reads, selects, creates, updates, deletes, filters, and derives managed State.

By the end of the tutorial, you will have a typed , an Angular service that owns the Feature boundary, a component that binds to reactive State, and a complete character workflow that can render, select, create, update, delete, filter, sort, and derive display-ready values from a managed collection.

Business Use Case
  • A product team needs a simple detail view that presents one record from a managed collection without exposing state-management mechanics in the component.
  • The feature must keep domain ownership in a service so UI code can stay focused on display logic, template binding, and user interaction.
  • The same structure should scale from a read-only detail screen to later workflows such as editing, validation, loading states, and testing without changing the core boundary.

Add-on Labs Are Choices, Not a Checklist

The complete tutorial makes many SDuX capabilities visible in one teaching application. A production feature rarely needs all of them. Use the decision guidance in each chapter to select the smallest set that satisfies your real state, timing, persistence, synchronization, and approval requirements.

The Mental Model
↑ top

Keep this ownership path in mind throughout the tutorial.

  • Angular UI events call a feature service.
  • The service is the only application layer that configures and updates its .
  • The pipeline resolves and shapes a candidate before committing a new immutable snapshot.
  • The component then reads that snapshot and derives presentation state for the template. 
Angular UI action
  → feature service method
  → FeatureCell request
  → FeatureCell pipeline execution
  → committed StateSnapshot
  → component Signal or Observable
  → template
Three Different Kinds of Setup
  • Structural registration:
    • provideVault() creates the application runtime
    • provideFeatureCell() registers a feature key, initial value, behaviors, and controllers.
  • Service connection and configuration: the @FeatureCell() decorator, injectVault(), and fluent methods bind one Angular service to that registration before initialize() activates it.
  • State requests: mergeState(), replaceState(), lifecycle methods, and asynchronous sources submit work after activation.
Candidate
The value currently moving through the pipeline.
Committed State
The last finalized value available to consumers.
StateSnapshot
The value together with loading, error, and value-presence metadata.
Behavior
A capability attached to a specific pipeline stage.
Controller
A capability that coordinates execution, such as timing, cross-tab initialization, or a pending decision.

Persistence, synchronization, timing, and policy controllers are optional branches. Add them only when a production requirement needs that capability; they are not required for the core FeatureCell path.
