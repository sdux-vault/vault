Step 11: Add a Dropdown
↑ top

This step upgrades the initial read path from showing the first committed record automatically to letting the user choose which committed record to inspect. The Feature registration, service-owned , and managed collection stay the same; only the UI-facing selection logic changes.

Assume the Angular mechanics are already familiar. The lesson here is narrower: keep Feature State in the service, keep selection state in the component, and derive the displayed record from the latest service-owned collection. To do that, replace the single displayed-character computed Signal with a read-only character collection, a selectedCharacterId Signal, a computed lookup for the selected record, and a small selection handler. In the template, add a select element that lists the registered characters and keep the detail panel bound to computed controller state instead of reaching into directly. The matching verification belongs in this same step: the updated component spec should prove the controller starts empty, accepts a valid selection, ignores unknown ids, and renders the selected record without moving ownership out of the service.

Take Action
  1. Open example.component.ts.
  2. Expose the committed collection and add Signals for the selected character id and selected character.
  3. Add a method that maps the dropdown value to a known character id from the current -managed collection.
  4. Open example.component.html.
  5. Add a dropdown above the details panel and render an empty state until the user selects a character from the managed collection.
  6. Update example.component.spec.ts to verify both the empty state and the selected-record state.
What to Look For
  • The service still owns the and does not change for this UI enhancement.
  • The selection Signal is presentation state owned by the component, not Feature State owned by the service.
  • The template continues to render computed, display-ready values instead of reading APIs directly.
  • The spec verifies the new UI behavior without changing the -owned Feature State contract.

Step 12: Complete Dropdown Tutorial
↑ top

The dropdown tutorial is complete once the page starts with no selected character, lists the registered collection in the picker, and updates the detail panel when the selection changes. The boundary has not moved: the service still owns the and the component still owns only UI selection state.

This is the smallest useful expansion of the initial tutorial: the application moves from one fixed read path to one user-directed read path without changing registration, service ownership, or application bootstrap structure. What changed is the proof that the same service-owned State can now support both an initial empty state and a selected-record view.

Take Action
  1. Return to the running Angular application.
  2. Confirm the details panel shows the empty state before a character is selected.
  3. Open the dropdown, choose a character, and confirm the details panel updates to the selected record.
  4. Choose a different character to verify the same read path reacts to the new selection.
What Changed From the Initial Example
  • The component now reads the full collection instead of assuming the first item is always the displayed record.
  • The selected character is derived from a local UI Signal and the latest reactive collection State.
  • The template now teaches user-directed selection on top of the same service-owned State.
