What the Tutorial Builds

You are going to build a Star Wars character component from the ground up. It starts as a small read view, then grows into a real feature with selection, create, read, update, and delete operations—all backed by a service-owned .

Along the way, the characters become a friendly way to explore the important parts of a feature: typed State, reactive read paths, service-owned updates, local selection, lifecycle operations, filters, reducers, errors, asynchronous input, persistence, and more. The story is fun; the State boundary is the part you can carry into your own application.

Your feature gains What happens
A character roster A typed collection gives every character a dependable shape.
A trusted home for State A service owns the and gives the view a reactive path to committed State.
A working character screen The view can display character details without configuring the directly.
CRUD interaction You can select characters, create new ones, update them, and remove them while State ownership stays with the feature service.
Room to go further Later chapters add lifecycle, errors, asynchronous input, persistence, observation, synchronization, and Pipeline topics.

End result: You finish with a small character command center: a view for exploring the roster and a feature boundary that keeps its committed State in the right place.

Build the Complete Feature: Chapters 1–7

Chapters 1–7 are one continuous build. You start with the foundation, give the character feature a typed State contract, and then add the pieces one at a time: a first read view, character selection, CRUD interaction, lifecycle operations, and display derivation. Each chapter builds on the application from the chapter before it, so by the end you have a complete feature application rather than a collection of disconnected examples.

Chapter Focus
Chapter 1: Welcome Establish the tutorial foundation and feature boundary.
Chapter 2: Display Character Expose committed State to a detail view.
Chapter 3: Display Characters Add local selection while the collection remains service-owned.
Chapter 4: Add/Edit Characters Add and update records through the feature service.
Chapter 5: Delete Characters Remove records while preserving feature State ownership.
Chapter 6: Lifecycle Work with lifecycle operations for the feature.
Chapter 7: Filters and Reducers Apply filtering, sorting, and display derivation before rendering.
Explore Focused Capabilities: Chapters 8–15

Chapters 8–15 begin with the complete application from Chapter 7. Each chapter then takes that working feature and explores one focused capability: errors, asynchronous input, delay, persistence, introspection, tab synchronization, distinct State changes, or stepwise Pipeline decisions. These chapters are focused experiments you can study one at a time, so you can see exactly what each capability adds without rebuilding the feature from scratch.

Chapter Focus
Chapter 8: Errors Represent and observe error State at the feature boundary.
Chapter 9: Async Input Resolve asynchronous inputs through the feature.
Chapter 10: Delay Controller Configure delayed State resolution.
Chapter 11: Encrypt and Persist Configure encrypted persistence for State.
Chapter 12: State Introspection Observe State at defined points in the feature lifecycle.
Chapter 13: Tab Sync Coordinate State across browser tabs.
Chapter 14: Distinct Until Changed Suppress redundant State emissions.
Chapter 15: Stepwise Pipeline Work with controlled Pipeline decisions.
Angular Tutorial

If you work in Angular, this tutorial gives you a hands-on path from an empty application to a complete, working feature. You will build a Star Wars character component, connect it to a service-owned , and watch committed State move into a reactive Angular view.

You will begin with Angular application setup and a typed character contract, then grow the feature chapter by chapter. Add character selection, create and update records, delete them, apply filters and reducers, and keep the component focused on the view while the service owns the feature State.

Once the core application is running, continue into focused Angular chapters for errors, asynchronous input, delay, encrypted persistence, State introspection, tab synchronization, distinct changes, and stepwise Pipeline decisions.
