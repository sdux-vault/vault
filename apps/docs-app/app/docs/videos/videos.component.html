Overview Videos

Pipeline Overview
↑ top

A complete walkthrough of the deterministic pipeline architecture in under 5 minutes. Covers all 10 stages, the 3 execution boundaries (Conductor, Orchestrator, FeatureCell), and why atomic pipeline execution means zero partial state updates in production.

Atomic Pipeline
↑ top

SDuX Vault's pipeline is atomic — the full pipeline completes and commits state, or nothing changes. No partial updates. No torn state. No intermediate values leak to observers. The pipeline either commits the entire result or rolls back completely — guaranteeing referential isolation at every boundary.

Vault Definition
↑ top

SDuX Vault is a TypeScript state management system that handles state as a Pipeline. Every state change is sealed behind strict, isolated boundaries enforced by the Vault. Each FeatureCell owns exactly one slice of application state — no central store, no selectors, no dispatched actions.

FeatureCell Definition
↑ top

A FeatureCell is the Conductor and Orchestrator — it is the SDuX Pipeline. This video explains how a FeatureCell conducts and orchestrates pipeline execution, how the Policy Layer eliminates race conditions, and how state flows through Pre-Processing, Processing, Output, and Post-Processing layers.

Conductor Definition
↑ top

The Conductor is the Policy Layer — it queues requests one at a time to determine if a new candidate is allowed into the pipeline. This eliminates race conditions by design.

Orchestrator Definition
↑ top

The Orchestrator streams state through the pipeline layers in order — Pre-Processing, Processing, Output, and Post-Processing. Each layer is split into stages that execute deterministically from top to bottom.
