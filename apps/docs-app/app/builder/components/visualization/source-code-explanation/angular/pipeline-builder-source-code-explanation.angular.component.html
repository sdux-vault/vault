Generated Example Files

This page contains the full, generated source output for the pipeline configuration you selected in the Builder. These files are designed to be copy/paste ready and follow best practices: the service owns the Vault, components consume the public state snapshot, and all updates flow through the service so the pipeline remains deterministic and consistent.

What You’re Looking At

  • installation — The minimal install command for the packages required by your selection.
  • app.config.ts — Registers the Vault runtime and defines the (key, initial state, and optional definition-time extensions).
  • example.service.ts — The service that owns the Vault instance and configures the runtime pipeline via the fluent API.
  • example.component.ts — A simple UI consumer that reads from the service’s reactive state snapshot and delegates state updates back to the service.

How to Use These Files

  • Start with installation and install the listed packages in your project.
  • Copy the files into your app (or use them as reference templates).
  • Rename placeholders (service name, state type, and FeatureCell key) to match your domain.
  • Keep Vault access inside the service — components should only use the service’s public state and call service methods to update state.

Important

  • The generated pipeline configuration is deterministic: it is installed during service construction and activated only when initialize() is called.
  • If you add or remove behaviors in the Builder, this output will change to match your new pipeline configuration.
  • Use the Copy button on each file to copy the source directly.
